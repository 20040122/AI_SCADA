# 概述

## 一、研制目标与指标

### （一）研制目标

本项目面向 DaoSCADA 工业测控平台的组态开发场景，研制工业测控代码生成软件，以人工智能技术辅助完成设备模型、组态界面、数据绑点和控制脚本等内容的生成，减少设备建模、控件选型、画面排布、属性配置及数据关联等重复性工作，提升工业组态开发效率，并通过规则约束、结构校验和人工复核机制保障生成结果的规范性、准确性与工程可用性。

本阶段以组态界面生成链路为研制重点，形成由规则库、控件素材 Agent、布局 Agent、微调 Agent 和绑点 Agent 组成的协同工作流程。系统根据自然语言需求提取所需控件，优先复用本地素材并对缺失素材进行生成；依据布局意图、设备数量和工艺拓扑计算控件位置及管线连接；通过自然语言和可视化交互对组态结果进行局部调整；最后完成控件与设备属性的语义匹配、人工确认、绑点结构生成及 DaoSCADA 上传。整个过程以 DaoSCADA 组态 JSON 为核心数据载体，兼顾智能生成的灵活性与工业规则的确定性。

### （二）主要技术指标

项目以《项目文档》中的技术要求和验收条件作为研制与测试基线，主要指标如下。指标达成情况及实测数据由专项测试报告给出。

| 指标类别 | 主要指标 |
| --- | --- |
| 系统架构与兼容性 | 后端采用 FastAPI，常规接口响应时间不超过 500 ms，不计第三方 API 调用时间；支持 Windows Server 2019 及以上、CentOS 8 及以上环境；前端采用 React，支持 Canvas/SVG 渲染及缩放、拖拽操作，适配 1920×1080 及以上分辨率；生成 JSON 能够被 DaoSCADA 现有渲染引擎解析，并支持与平台功能对接。 |
| 数据与第三方依赖 | 素材数据采用 SQLite 与文件系统组合存储，向量检索采用本地 Chroma，具备离线存储和本地检索能力；大模型及文生图接口采用开源或经确认的商业服务，目标故障率不高于 0.5%，并明确依赖版本与兼容关系。 |
| 规则与校验 | 按 JSON Schema Draft-07 建立画布、控件和绑点规则，限制字段类型、必填项及枚举取值；合法与非法 JSON 判断准确率达到 100%，至少准备 3 个合法示例和 3 个非法示例，能够定位字段缺失、类型错误和枚举越界等问题。 |
| 控件检索与生成 | 自然语言需求中的设备、状态和风格等关键信息提取准确率不低于 90%；5 条不同查询的控件检索准确率不低于 90%；相似度大于 0.85 时优先复用本地素材；生成图像清晰度不低于 128×128 像素，批量生成效率不低于 10 个/分钟，生成素材合格率不低于 95%；素材管理操作响应时间不超过 100 ms。 |
| 自动布局 | 画布、素材及布局需求提取准确率不低于 90%，控件坐标精度不大于 1 px；同类设备间距小于 200 px，管路与设备保持有效连接，显示类控件按规则进入指定区域，布局约束执行率达到 100%；元素数量大于 20 时采用辅助排版算法；前端渲染延迟不超过 1000 ms，重叠和孤立控件检测准确率达到 100%；3 个典型场景均通过 Schema 校验和人工评审。 |
| 智能微调 | 单选、框选及多选准确率达到 100%，选中控件的标识、类型、位置等上下文提取完整率达到 100%；支持换位、改色、对齐、缩放、删除等自然语言指令，仅返回符合 RFC 6902 的 JSON Patch，响应时间不超过 1000 ms，典型指令响应准确率不低于 80%；修改支持预览、接受和撤销，回滚后无数据残留。 |
| 数据绑点 | 设备变量清单解析准确率不低于 95%；自动关联采用语义相似度、名称和编号等信息，标准清单 Top-1 匹配准确率不低于 75%；重复绑定和重复变量等冲突检测准确率达到 100%，能够正确识别 3 条预置冲突场景；生成的绑点 JSON 通过 Schema 校验，并支持人工修改与确认。 |

## 二、研制范围与主要工作

### （一）研制范围

项目总体范围覆盖 DaoSCADA 设备模型、组态界面、绑点信息和控制脚本的智能化生成，以及相关规则、素材、预览、校验和平台集成能力。结合当前代码成果，本阶段重点打通“需求描述—控件检索或生成—画布布局—局部微调—数据绑点—规则校验—平台上传”的组态界面研制链路。设备模型和控制脚本属于总体建设范围，当前仓库的主体实现集中在组态画面及其配套数据生成能力，后续可在既有 Agent、Schema 和接口体系上继续扩展。

软件采用前后端分离结构。前端以 React、TypeScript、Vite 和 Zustand 构建统一工作台，提供规则查看与校验、素材检索与生成、布局预览、画布交互微调、绑点复核等功能；后端以 FastAPI 提供控件、画布、校验、素材、图像生成和绑点接口；Agent 层负责自然语言理解及任务决策，布局计算、几何约束、补丁编译、冲突检查等确定性逻辑负责约束生成结果；数据层使用 JSON Schema、JSONL、SQLite、文件系统、Chroma 向量库及本地中文嵌入模型组织规则与素材数据，并通过上传服务与 DaoSCADA 平台衔接。

### （二）主要工作

1. 建设 JSON Schema 规则与校验能力。围绕控件资源、画布结构、布局意图和绑点数据建立规则文件及前端规则库，采用 Draft-07 校验字段结构、类型、必填项和枚举值；在基础 Schema 校验之外，引入布局语义检查和 AI 辅助检查，统一输出错误路径、错误类型、提示信息和警告信息，为各 Agent 的输入、输出及最终上传提供质量门禁。

2. 研制控件素材 Agent。通过大模型从自然语言描述中提取控件关键词，结合标准控件目录、同义词映射和本地中文向量模型完成精确检索与语义检索；对未命中的控件启动文生图任务，提供生成、状态轮询、预览、重生成、确认和放弃流程。确认后的素材上传至 DaoSCADA，写入 JSONL 与 SQLite，并触发 Chroma 索引更新，从而形成“检索优先、缺失生成、确认入库、持续复用”的素材闭环。

3. 研制自动布局 Agent。根据结构化需求、画布尺寸和已选素材并行生成背景画布与布局意图中间表示，结合角色尺寸、区域划分、排列方式、设备数量和附件关系等规则确定控件尺寸与坐标；根据工艺描述生成设备连接关系，校验拓扑、端点和端口后序列化为 DaoSCADA 管线节点；最终拼装画布、控件、标签、管线和素材快照，计算内容边界并输出符合 DaoSCADA 格式的组态 JSON。

4. 研制组态微调 Agent。前端画布支持缩放、平移、单选、多选、拖拽和等比例缩放，并将选中元素及完整画布作为微调上下文；后端将自然语言指令转换为受约束的动作，再由确定性几何算法完成移动、换位、对齐、分布、缩放、改色、重命名、删除和新增控件等操作，输出最小化 JSON Patch。前端对补丁进行差异预览，支持接受或撤销，并同步更新控件标签、管线关系、修改历史和后续绑点数据源。

5. 研制数据绑点 Agent。对标准化设备属性清单进行编码、文件大小、行数、表头、空值和重复项检查；从最新布局或已确认的微调结果中定位目标控件，通过属性名精确匹配和本地嵌入模型语义匹配生成候选项、相似度、匹配依据和置信度；提供逐条选择、批量确认及绑定前后对比，检查伪造候选、重复选择、目标歧义和 Schema 错误后，将确认结果写入 DaoSCADA 控件属性并生成可上传的绑定画面 JSON。

6. 完成素材、任务与平台集成服务。建立素材主库、查询结果库、控件目录热更新和生成任务生命周期管理机制；对图像生成任务实施排队、超时、过期清理和错误分类；上传前校正控件宽高比、同步标签位置、重建管线并检查新增或扩大重叠，校验通过后将组态文件提交至 DaoSCADA 指定目录。

7. 建设统一 Web 工作台与测试体系。前端设置 Schema 校验、控件 Agent、布局 Agent、微调 Agent 和绑点 Agent 五个功能区，通过共享状态串联素材选择、布局结果、微调版本和绑点来源；后端按路由、服务、Agent、工具和数据层拆分职责。项目针对接口、Agent、布局意图、几何计算、管线序列化、画布上传、素材热更新、JSON Patch、绑点匹配及前端状态管理等关键环节建立自动化测试，为后续性能验证、场景验收和功能扩展提供基础。
