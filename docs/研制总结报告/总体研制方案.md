## 2.1 系统总体架构

系统总体采用分层解耦、Agent 协同和人机闭环相结合的架构，自上而下划分为用户交互、前端预览、FastAPI 接口服务、Agent 任务编排以及模型服务与目标平台五个层次。各层通过标准化接口传递自然语言需求、素材信息、组态 JSON、JSON Patch 和绑点配置，在保持模块独立性的同时，串联形成“控件检索与生成—自动布局—人机微调—数据绑点—平台发布”的完整业务链路。系统并非将组态文件完全交由大模型自由生成，而是由大模型负责需求理解、语义提取和方案决策，由规则、Schema、几何算法和数据注册表负责结果约束，再由用户完成关键结果复核，最终兼顾智能生成效率、工业规则确定性和成果可追溯性。

用户层面向组态设计人员，承接控件搜索、自然语言布局、微调画布和绑点复核等操作。设计人员可以输入设备组成、数量、区域关系和工艺连接等需求，也可以通过点击、多选、拖拽和缩放等方式直接调整画布，并对 AI 返回的素材候选、微调补丁及绑点候选进行确认。系统将人工确认设置为素材入库、补丁生效和绑点构建等关键节点的前置条件，使自动生成结果始终处于可预览、可修改和可撤销的受控状态。完成的组态文件上传至 DaoSCADA 后，由平台执行最终解析与渲染，形成从需求输入到组态成果展示的闭环。

前端预览层采用统一 Web 工作台组织 Schema 校验、控件 Agent、布局 Agent、微调 Agent 和绑点 Agent 五个功能页面。Schema 校验页面用于查看画布、控件、布局及绑点规则，并对输入 JSON 执行结构检查；控件 Agent 页面负责自然语言检索、候选素材展示、缺失素材生成和确认入库；布局 Agent 页面负责输入画布标题、尺寸及工艺描述，展示自动生成的设备、标签和管线；微调 Agent 页面继承布局结果，支持控件选择、拖拽、等比例缩放以及自然语言局部调整；绑点 Agent 页面从最新布局或已确认的微调版本中取得画布，导入设备属性清单，展示匹配候选、置信度和绑定前后差异。前端使用共享状态维护素材选择结果、画布版本、管线数据、待确认补丁和绑点来源，保证各页面之间的数据连续性；同时通过 Canvas/SVG 组合渲染组态背景、控件、文字标签和管线，提供缩放、平移、选择和实时预览能力。

FastAPI 接口服务层是前端与智能能力之间的统一边界，按业务域划分为校验接口、控件与素材接口、图像生成接口、布局与微调接口、绑点接口以及画布上传接口。该层负责请求模型校验、依赖注入、资源生命周期管理、统一响应封装和异常映射，并将模型不可用、调用超时、输出不合法、素材缺失、拓扑冲突和上传失败等情况转换为明确的接口状态。控件与素材接口提供查询、素材列表及检索结果保存；图像生成接口以异步任务方式提供创建、轮询、预览、重生成、确认和放弃；画布接口负责布局生成、微调和上传；绑点接口负责清单预览、候选匹配和绑定构建。接口层不直接承载复杂业务判断，而是将任务交由对应 Agent 和服务组件执行，从而使传输协议、业务编排和核心算法保持清晰边界。

Agent 任务编排层是系统智能能力的核心，包括校验 Agent、控件 Agent、素材生成任务管理、布局 Agent、微调 Agent 和绑点 Agent。校验 Agent 将 JSON Schema 硬校验、布局语义规则与大模型辅助审查相结合；控件 Agent 先从自然语言中提取标准控件名称，再通过精确匹配、同义词映射和向量检索返回候选；素材生成任务管理器在本地目录中维护生成任务的排队、状态、预览、过期回收和确认入库；布局 Agent 并行生成背景画布和布局意图中间表示，再调用确定性算法计算区域、尺寸和坐标，并根据工艺描述生成、校验和序列化管线；微调 Agent 将自然语言转换为受约束的动作，由几何算法编译为最小化 JSON Patch，避免直接返回不可控的全量文件；绑点 Agent 通过属性名精确匹配和中文语义相似度生成候选，结合人工确认结果构建 DaoSCADA 绑点结构，并在输出前执行目标歧义、重复选择及 Schema 检查。各 Agent 共享统一的大模型客户端和本地规则资源，但分别封装自身的输入、输出、重试与校验逻辑，便于独立测试和后续扩展。

模型服务与目标平台层由大语言模型服务、文生图服务和 DaoSCADA 平台构成。大语言模型主要参与控件关键词提取、布局意图生成、工艺拓扑理解、微调动作解析和语义审查，系统通过 OpenAI 兼容客户端调用 DeepSeek 模型，并通过结构化提示、输出解析、重试和结果校验控制模型输出。文生图服务在本地控件目录无法满足需求时生成工业风格控件图片，生成结果只有在用户确认后才上传并写入素材目录、SQLite 和 JSONL，同时更新 Chroma 向量索引。DaoSCADA 平台作为最终运行与展示环境，接收控件资源和组态 JSON；系统在上传前校正控件宽高比、同步标签位置、重建管线、检查新增或扩大的重叠并再次执行 Schema 校验，确保提交内容能够被目标平台直接解析。除外部模型服务外，系统还依托 JSON Schema、布局配置、管线模板、控件映射、SQLite、JSONL、Chroma 和本地 BGE 中文嵌入模型构成本地数据支撑体系，使规则、素材和检索能力可持续维护，并降低对外部服务的依赖范围。

## 2.2 技术路线与选型

### 2.2.1 总体技术路线

系统采用“自然语言驱动、规则约束生成、本地资源优先、确定性算法落地、人工确认闭环”的总体技术路线。自然语言模型用于解决传统规则难以覆盖的语义理解问题，包括从用户描述中识别控件、理解设备数量与工艺关系、判断局部调整意图以及辅助发现语义异常；JSON Schema、控件注册表、布局规则、几何计算和绑点处理器用于限定字段、枚举、尺寸、坐标、拓扑与数据结构；前端预览和确认机制负责将智能生成结果纳入人工控制。该路线将概率性模型限制在需求理解和方案建议环节，将对 DaoSCADA 文件有直接影响的结构拼装、坐标计算、补丁生成、冲突检测和上传校验交由可重复执行的程序完成，从而降低模型幻觉对工业组态成果的影响。

业务流程以组态 JSON 为主数据对象。控件 Agent 首先形成可用素材集合并写入查询结果库，布局 Agent 读取该集合生成布局意图、控件节点及管线数据，微调 Agent 在同一份画布上产生增量补丁，绑点 Agent 再从最新确认版本构建属性绑定，上传服务完成最终校正和平台提交。各阶段既可按顺序组成端到端流程，也可以通过独立接口单独调用；阶段之间使用明确的数据结构而非隐式会话传递，前端通过版本号和来源文件名判断布局、微调及绑点数据是否一致，避免旧结果覆盖新状态。

### 2.2.2 前端技术选型

前端选用 React、TypeScript 和 Vite 构建单页应用。React 适合将规则库、素材卡片、布局面板、画布和绑点表格拆分为可复用组件，TypeScript 用于约束接口响应、画布节点、管线、补丁和绑点候选等复杂数据结构，Vite 提供开发期快速构建与模块热更新能力。全局业务状态采用 Zustand 管理，分别维护素材、布局、微调、规则和绑点状态，并通过布局修订号、微调修订号、源文件名和待确认补丁控制跨页面数据同步。

画布预览采用 DOM、Canvas 交互思想与 SVG 管线渲染相结合的实现方式。控件和标签按照 DaoSCADA 坐标系进行缩放与偏移，SVG 负责绘制管线、方向箭头和连接路径，前端几何工具负责拖拽快照、批量移动、等比例缩放、障碍物规避和正交管线路由。该方案能够直接复用后端生成的节点坐标，并在微调时同步更新 JSON 数据、控件标签和管线关系，使页面预览与最终上传文件保持一致。

### 2.2.3 后端与接口技术选型

后端选用 Python 3.9 和 FastAPI，数据模型采用 Pydantic v2。FastAPI 提供异步请求处理、类型化参数校验、依赖注入和 OpenAPI 接口描述，适合同时承载模型调用、数据库访问、文件处理和平台上传等任务。应用通过生命周期管理统一初始化和关闭 SQLite、Chroma 控件目录、各类 Agent 以及图像生成后台任务，避免接口请求重复加载模型和索引。接口返回采用统一响应结构，业务异常按输入错误、上游服务错误、服务不可用和超时等类型映射为相应 HTTP 状态，便于前端准确展示失败原因并决定是否重试。

后端按路由层、服务层、Agent 层、工具层和数据层组织。路由层负责协议转换和异常映射；服务层负责 CSV 解析、素材管理、生成任务、画布上传等应用流程；Agent 层负责任务编排；工具层封装控件提取、布局意图、坐标计算、管线序列化和微调几何算法；数据层负责 Schema、配置文件、本地数据库和向量索引。分层后，各模块可以使用替身模型、临时数据库或固定输入独立测试，降低外部 API 对自动化测试的影响。

### 2.2.4 模型、检索与素材技术选型

大语言模型通过 OpenAI 兼容 SDK 接入，当前配置以 DeepSeek 模型为主。采用兼容接口可以在不改变 Agent 业务逻辑的情况下替换模型地址和模型名称，并通过环境变量隔离 API 密钥。模型调用采用结构化系统提示和用户提示，输出进入业务流程前必须经过 JSON 解析、字段白名单、目标节点检查及语义规则校验；对临时故障和格式错误设置超时、重试及明确的错误分类，避免无效输出直接进入组态文件。

本地语义检索采用 BGE-small-zh 中文嵌入模型和 Chroma 向量库。控件目录以 JSONL 保存标准名称、资源路径和尺寸等权威数据，控件映射文件维护同义词与允许候选集合，检索时先执行标准名称精确匹配和映射匹配，未命中时再使用向量相似度排序。绑点模块复用本地嵌入模型，对属性名称进行精确或语义匹配，并输出分值、领先差值、置信度和匹配依据。该方案将目录约束与语义召回结合，既保留自然语言检索能力，又避免向用户返回注册表之外的控件或绑点对象。

缺失素材由 Qwen 文生图服务生成。系统采用异步任务队列隔离耗时较长的图像生成调用，为每个任务维护随机种子、状态、预览文件、过期时间和错误码；用户可以查看预览、重新生成或放弃，只有确认结果才进入正式素材库。确认流程依次完成 DaoSCADA 资源上传、JSONL 追加、SQLite 保存和控件目录热加载验证，从而保证前端可见素材、本地索引和目标平台资源的一致性。

### 2.2.5 规则、布局与微调技术路线

规则体系以 JSON Schema Draft-07 为基础，分别描述画布、控件和绑点结构，并辅以布局角色尺寸、区域排列、设备附件关系、管线端口和控件映射等配置。校验流程同时包含结构校验、布局语义检查和大模型辅助检查，统一返回字段路径、错误类型、说明和警告。Schema 和规则配置均以文件形式独立保存，便于随着 DaoSCADA 描述规范演进而更新，前端规则页面同步展示字段、派生规则及合法和非法示例。

自动布局采用“布局意图中间表示加确定性坐标计算”的路线。系统将设备清单、工艺结构、区域要求和排列要求转换为布局意图，基于画布内容区域划分设备组位置，根据控件角色和素材原始比例计算尺寸，再生成设备实例和标签节点。管线生成先从需求中提取工艺段，结合实际节点目录解析源端、目标端和端口，经过拓扑一致性、选择器、重复边和端点合法性检查后，序列化为 DaoSCADA 管线节点。背景画布与布局意图并行生成，以减少串行等待时间；最终组装时写入素材快照、内容边界和修改时间，并执行画布 Schema 校验。

微调采用“模型解析动作、程序编译补丁”的路线。后端向模型提供完整画布、选中节点和允许动作集合，模型只负责返回移动、换位、对齐、分布、缩放、改色、重命名、删除或新增等结构化动作；程序根据画布边界、控件比例、标签关系、碰撞和放置空间计算最终结果，再编译为 RFC 6902 JSON Patch。前端保存应用补丁前的画布和管线快照，先展示差异预览，用户接受后记录历史，拒绝时恢复快照。该机制减少全量 JSON 往返，防止模型意外修改未选中对象，并为撤销和后续绑点提供稳定版本。

### 2.2.6 绑点、存储与平台集成技术路线

绑点流程采用“标准清单校验、目标定位、候选匹配、人工确认、受控构建”的路线。当前系统以标准化 CSV 作为设备属性需求输入，对编码、文件大小、行数、表头、列数、空值和重复组合进行检查；随后在画布中按控件显示名称定位目标节点，根据控件类型选择对应绑定处理器。候选匹配优先采用属性名精确匹配，未命中时使用本地中文向量相似度返回限定数量的候选，并按分值和候选领先程度计算置信度。构建阶段重新核对候选合法性、重复 assignment、同一目标重复绑定和注册表存在性，生成绑定前后对比；只有画布 Schema 与绑点 Schema 同时通过时才返回可上传结果。

本地数据采用 SQLite、JSONL、Chroma 和文件系统组合存储。SQLite 保存素材元数据和用户确认的查询结果，JSONL 保存可版本化、便于人工审阅的控件目录及绑点注册表，Chroma 保存控件向量索引，文件系统保存图片、生成预览、组态结果和布局中间数据。该组合避免引入重型数据库服务，适合本地部署和离线检索，同时能够按数据性质分别满足结构化查询、追加维护、语义检索和大文件存储需求。

平台集成通过 HTTP 上传服务完成。组态上传前，系统依据素材元数据或素材库记录解析控件原始宽高比，在当前边界内进行等比例校正，并同步调整关联标签；若提供独立管线数据，则移除旧的受管管线并重新序列化。系统比较校正前后的控件重叠关系，阻止新增重叠或重叠面积扩大，再执行最终 Schema 校验，校验通过后将 JSON 文件上传至 DaoSCADA 指定目录。素材确认时使用同一平台接口上传图片资源，确保组态文件引用的资源在目标环境中可用。

### 2.2.7 质量保障与可扩展性

项目通过规则校验、程序防护和自动化测试三类措施保障质量。规则校验覆盖输入、Agent 输出、补丁和最终上传文件；程序防护覆盖模型超时、格式错误、非法目标、文件限制、任务过期、素材比例、管线拓扑及绑定冲突；自动化测试覆盖 FastAPI 路由、Agent 行为、控件目录热更新、布局意图、几何计算、管线序列化、画布上传、微调补丁、绑点匹配以及前端状态与工具函数。代码遵循 Python 和 TypeScript 的类型约束，并通过 Ruff、TypeScript 编译和前端测试实施持续检查。

系统的扩展点主要位于 Agent、处理器、规则文件和外部服务适配器。新增控件类型可通过扩展控件目录和映射文件完成，新增布局策略可在区域划分与角色尺寸配置中扩展，新增绑点控件可注册新的绑定处理器，模型服务可通过兼容客户端或生成器接口替换，DaoSCADA 上传目录和服务地址可通过环境配置调整。设备模型生成和控制脚本生成可继续沿用现有的“结构化输入—Agent 编排—规则校验—人工确认—平台发布”框架接入，从而在不破坏现有组态链路的前提下扩展总体功能范围。
