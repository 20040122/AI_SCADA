## 4. 模块依赖关系

```text
3.1 JSON Schema 规则库
  ├── 约束 3.2 控件素材数据
  ├── 校验 3.4 自动布局输出
  ├── 校验 3.5 Patch 应用后画布
  └── 校验 3.6 绑点 JSON

3.2 控件素材库
  └── 提供素材检索底座给 3.3 控件素材 Agent

3.3 控件素材 Agent
  └── 输出控件候选给 3.4 自动布局 Agent

3.4 自动布局 Agent
  ├── 输出画布 JSON 给 3.5 人机微调 Agent
  └── 输出 control 列表给 3.6 数据绑点 Agent

3.5 人机微调 Agent
  └── 微调接受后触发 3.6 增量绑点或重新校验

3.6 数据绑点 Agent
  └── 输出 binding JSON，与 canvas/control 共同组成最终组态 JSON
```

## 5. 风险与应对

| 风险 | 影响模块 | 风险说明 | 应对措施 |
|------|----------|----------|----------|
| LLM 调用不稳定或输出格式异常 | 3.3、3.4、3.5、3.6 | 意图提取、布局微调、Patch 生成可能失败 | 全部模块保留规则兜底；LLM 输出强制 JSON；失败时返回可解释错误或进入人工复核 |
| Schema 与实际画布 JSON 字段不一致 | 3.1、3.4、3.5、3.6 | 可能导致布局或 Patch 校验误报 | 先完成 3.1 并作为统一准入；联调阶段集中修正字段映射 |
| 3.5/3.6 几乎全量新建工期紧 | 3.5、3.6 | PatchAgent 和 BindingAgent 涉及前后端+LLM 多条线 | 优先保核心链路，前端辅助功能可后续迭代；提前冻结接口定义 |
| 绑点匹配准确率不足 | 3.6 | 跨语言匹配和点表规范差异大 | 三路匹配 + 人工复核作为必须路径；先保证不误绑，再优化自动确认率 |
| 前端差异预览交互复杂 | 3.5 | 接受/撤销和双快照可能产生状态不同步 | 采用 before/after/current 三快照模型；所有 Patch 应用后再渲染 |
| 端到端联调时间压缩 | 3.1-3.6 | 多模块串联可能暴露接口不一致 | 每个模块完成当天同步输出接口样例，7/7前完成接口冻结 |
