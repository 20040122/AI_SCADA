# 3.2 控件素材库

## 3.2.1 概述

控件素材库管理系统中所有可供组态界面使用的控件资源，提供自然语言检索、语义匹配、向量存储和查询记录保存能力，是 AI 布局生成和绑点生成的基础数据源。

### 核心数据流

```text
control.jsonl ──→ Chroma 向量库 (bge-small-zh-v1.5)
     │                  │
     ▼                  ▼
  SQLite ◄── control_schema.json 校验
     │
     ▼
检索流程：LLM 提取意图 → Chroma 向量检索 → SQLite LIKE 兜底
     │
     ▼
后端 API：/api/control/search + /api/material/*
     │
     ▼
前端：类型定义 + API 调用
```

## 3.2.2 数据存储

### 2.1 控件数据源 — control.jsonl

**文件位置**：`data/control.jsonl`

JSONL 格式，每行一个控件（当前 166 条记录）：

```json
{"displayName":"高低温试验箱","image":"symbols/_public/devices/高低温试验箱.json","width":500,"height":800}
{"displayName":"水泵","image":"symbols/demo/water treatment/水泵.json","width":131,"height":116}
{"displayName":"指示灯","image":"symbols/test/wangj/指示灯.json","width":30,"height":30}
```

部分控件带 `boundExtend`（点击热区扩展）：

```json
{"displayName":"发光条","image":"symbols/机加工自动化生产线/发光条.json","width":128,"height":4,"boundExtend":24}
{"displayName":"数值显示2-小","image":"symbols/现场控制系统/样式修改/数值显示2-小.json","width":78,"height":24,"boundExtend":2}
```

**数据类型**：`data/control_schema.json` 使用 JSON Schema Draft-07 约束：

| 字段 | 类型 | 必填 | 可为 null | 说明 |
|------|------|------|-----------|------|
| `displayName` | string | ✅ | ❌ | 控件显示名称，如"高低温试验箱" |
| `image` | string | ✅ | ❌ | 资源路径，以 `symbols/` 或 `assets/` 开头 |
| `width` | number | ✅ | ✅ | 宽度，null 时由引擎自动计算 |
| `height` | number | ✅ | ✅ | 高度，null 时由引擎自动计算 |
| `boundExtend` | number | ❌ | ❌ | 边界扩展像素值 |
| `additionalProperties` | false | — | — | 禁止未定义字段 |

**前端 TypeScript 接口**（`web/scada/src/types/asset.ts`）：

```typescript
export interface ControlItem {
  displayName: string;
  image: string;
  width: number;
  height: number;
}
```

### 2.2 SQLite 素材库 — material.db

**文件位置**：`data/material.db`

由 `data/material_db.py` 的 `MaterialDB` 类管理，包含两张表：

#### controls 表（素材主表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `displayName` | TEXT PK | 控件显示名称 |
| `image` | TEXT NOT NULL | 资源路径 |
| `width` | REAL | 宽度 |
| `height` | REAL | 高度 |
| `source` | TEXT NOT NULL DEFAULT 'local' | 来源标识 |
| `created_at` | TEXT | 创建时间（自动填入当前时间） |

#### query_results 表（查询历史）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK AUTOINCREMENT | 自增主键 |
| `query` | TEXT NOT NULL | 用户原始查询 |
| `displayName` | TEXT NOT NULL | 检索命中的控件名称 |
| `image` | TEXT | 资源路径 |
| `width` | REAL | 宽度 |
| `height` | REAL | 高度 |
| `similarity` | REAL NOT NULL DEFAULT 0.0 | 相似度分值 |
| `source` | TEXT NOT NULL DEFAULT 'vector' | 检索来源 |
| `created_at` | TEXT | 创建时间 |

#### 初始化流程

```
MaterialDB.init_db()
  → 创建 controls 表和 query_results 表
  → 执行字段迁移（兼容旧版本缺少 similarity/source 列）
  → _seed_from_jsonl()
    → 读取 control.jsonl 全量加载
    → 对比 SQLite 已有数据，删除已不在 jsonl 中的旧记录
    → 批量写入/更新到 controls 表
```

### 2.3 Chroma 向量库

**文件位置**：`data/chroma/`

| 文件 | 职责 |
|------|------|
| `embedding.py` | 加载 embedding 模型 |
| `control_chunk.py` | ChromaDB 持久化客户端、文档构建、检索、文件监听 |

#### Embedding 模型

```python
# data/chroma/embedding.py
MODEL_NAME = "model/bge-small-zh-v1.5"
```

使用本地部署的 `bge-small-zh-v1.5` Sentence Transformer 模型，单例模式加载。

#### Collection 配置

- Collection 名称：`control_chunks`
- 距离度量：`cosine`
- 持久化路径：`data/chroma/db/`

#### 文档构建

每条控件数据存入 Chroma 时，文档内容格式为：

```
SCADA 控件：{displayName}，宽度 {width}，高度 {height}，资源路径 {image}
```

查询时自动加上前缀：

```
为这个句子生成表示以用于检索相关文章：{query_text}
```

#### Chroma 文档示例

| 原始数据 | 构建的文档 |
|---------|-----------|
| `{displayName:"水泵", width:131, height:116, image:"symbols/..."}` | `SCADA 控件：水泵，宽度 131，高度 116，资源路径 symbols/demo/water treatment/水泵.json` |

#### Metadata 结构

```python
{
  "type": "control",
  "displayName": "水泵",
  "width": 131,
  "height": 116,
  "image": "symbols/demo/water treatment/水泵.json"
}
```

#### 文件变更监听

使用 `watchdog` 库监听 `control.jsonl` 文件变更：

- 启动时计算文件 SHA256 hash
- 检测到 hash 变化时自动触发 `reseed()`
- `reseed()` 对比 Chroma 中已有 ID，删除已不存在的控件，upsert 新增/变更的控件

## 3.2.3 检索流程

### 3.1 整体流程

```
用户查询 "2个指示灯和1个水泵"
  ↓
ControlAgent.process_query()
  ┌───────────────────────────────────────┐
  │ 第一步：LLM 提取意图                  │
  │  → 调用 DeepSeek 提取控件关键词+数量  │
  │  → 结果：[{name:"指示灯",count:2},    │
  │           {name:"水泵",count:1}]      │
  │  → 带 cache，同一 query 不重复调用   │
  └───────────────────────────────────────┘
  ↓
  ┌───────────────────────────────────────┐
  │ 第二步：多路检索                      │
  │  对每个 keyword 执行：                 │
  │  1. Chroma 向量检索（阈值 0.55）       │
  │  2. 相似度 < 0.55 → SQLite LIKE 兜底  │
  │  3. 去重，取 Top-5                     │
  └───────────────────────────────────────┘
  ↓
返回 KeywordResult[]
  → keyword / count / candidates[].displayName
  → candidates[].similarity / candidates[].source
  → missed[]（所有检索均未命中的关键词）
```

### 3.2 LLM 意图提取

**实现位置**：`model/control_agent.py`

**Prompt 模板**：

```
你是工业SCADA控件检索专家。从用户的自然语言描述中提取所需的控件关键词及数量。

控件库中可用的控件名称列表：
{control_names}

提取要求：
1. 从用户描述中提取控件关键词，关键词必须优先从上方列表中选取
2. 若用户描述的控件不在列表中，提取最接近的关键词用于模糊检索
3. 若用户未指定数量则默认为1

输出JSON：
{"controls": [{"name": "关键词", "count": 数量}]}
```

调用 LLM 时使用 `response_format: json_object` 和 `reasoning_effort: low` 确保结构化输出。

**缓存**：`_extract_cache` 字典，以 `(query, control_names_str)` 为 key，相同 query+控件库不重复调用 LLM。

### 3.3 多路检索

**实现位置**：`model/search_service.py`

```
search_controls_with_threshold(keywords, n_results=5)
  → 对每个 keyword 调用 Chroma query
  → 计算 similarity = 1 - cosine_distance
  → similarity >= 0.55 标记为 matched
  → matched=true → source="vector"
  → matched=false（< 0.55）→ SQLite LIKE 兜底 → source="sqlite"
```

**SQLite 兜底**：`MaterialDB.search_by_name(keyword)` 执行 `LIKE '%keyword%'` 模糊匹配。

**去重逻辑**：以 `displayName` 为唯一键去重。

**检索结果示例**：

```
用户查询："水泵运行状态"
  → LLM 提取：[{name:"水泵", count:1}, {name:"指示灯", count:1}]
  → Chroma 检索 "水泵":
      - 水泵       sim=0.89 ✅ matched
      - 水池       sim=0.45 ❌ → SQLite 兜底
  → Chroma 检索 "指示灯":
      - 指示灯     sim=0.92 ✅ matched
      - 运行状态灯 sim=0.78 ✅ matched
```

### 3.4 相似度阈值策略

| 相似度范围 | 处理方式 |
|-----------|---------|
| ≥ 0.55 | 判定为向量命中，保留在候选列表 |
| < 0.55 | 降级到 SQLite LIKE 兜底 |

> 注：当前系统未实现 PRD 中 >0.85 直接复用、<0.70 调用文生图的策略，这些是后续待实现。

## 3.2.5 前端类型定义

**文件位置**：`web/scada/src/types/asset.ts`

```typescript
// 基础控件（与 control_schema.json 一致）
export interface ControlItem {
  displayName: string;
  image: string;
  width: number;
  height: number;
}

// 检索候选（加 similarity/source）
export interface ControlCandidate {
  displayName: string;
  image: string;
  width: number;
  height: number;
  similarity: number;
  source: string;
}

// 关键词检索结果
export interface KeywordResult {
  keyword: string;
  count: number;
  candidates: ControlCandidate[];
}

// 素材库列表项
export interface MaterialItem {
  displayName: string;
  image: string;
  width: number;
  height: number;
  source: string;
  similarity: number;
}

// 完整查询结果（预留）
export interface AssetQueryResult {
  entities: {
    deviceType: string;
    state: string;
  };
  rewrite: string;
  matches: ControlItem[];
  missed: string[];
}
```

```
           │
           ▼
    web/scada/src/api/       →  前端调用
```
